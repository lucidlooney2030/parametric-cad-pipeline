# Parametric CAD Pipeline

**Long-lived, versioned system for turning ideas into simulation-verified 3D-printable parts.**

Built to end the cycle of lost-in-translation geometry from voice/chat. Code is the source of truth. Conversation is the review layer.

## The Pipeline (every build follows this)

1. **Idea capture** — plain language, no dimensions yet. Logged in `projects/<name>/IDEA.md`.
2. **Parameter definition** — all dimensions as named variables in a single `parameters.py` (or `.scad`). No magic numbers in geometry code.
3. **Geometry generation** — CadQuery / build123d (preferred) or OpenSCAD. One script per part, importing shared params. STL is *output only*.
4. **Assembly & fit checks** — mating parts share the same parameter source so clearances, bores, and stack heights cannot drift.
5. **Simulation pass** (mandatory before print):
   - Clearance / interference checks (boolean, bounding-box, fit coupons).
   - FEA stress / deflection where loads matter (e.g. rotor under magnet pinch, crank torque).
   - Kinematic / stack verification for multi-part builds (generators, mechanisms).
6. **Export** — binary STL + optional STEP. Regenerated by script, never hand-edited.
7. **Print notes + debrief** — orientation, supports, material, measured vs predicted results. Closes the loop.

## Why this exists

Natural language is a lossy channel for 3D geometry. Every dimension survives two translations (idea→words, words→coordinates) and bleeds precision. This repo makes the **script** the single source of truth so nothing is re-derived from chat.

## Quick start (new project)

```bash
cp -r projects/_template projects/my-build
# edit parameters.py, geometry scripts, then:
python -m projects.my-build.simulate   # clearance + FEA
python -m projects.my-build.export     # → stl/
```

## Simulation requirements

- `cadquery` + `cq-kit` (or `build123d`)
- `numpy` / `scipy` for simple FEA or clearance math
- Optional: `gmsh` + `fenics` / CalculiX for full FEA; `trimesh` for mesh checks

See `docs/SIMULATION.md`.
